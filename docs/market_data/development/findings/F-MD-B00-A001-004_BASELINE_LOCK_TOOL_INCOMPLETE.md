# F-MD-B00-A001-004 — Baseline lock tool does not emit the standard minimum field set

- Status: `OPEN`
- Severity: `P2`
- Stage / Attempt / Baseline / Epoch: `MD-B00` / `MD-B00-A001` / `MD-B00-A001-BL001` / `MD-REBASELINE-20260820-001`
- Owning stage for remediation: `MD-B00`
- Artifact: `development/implementation/tests/CreateMarketDataWorkBaselineLock.php`

## Finding

`WORK_BASELINE_LOCK_STANDARD.md` requires every lock to bind, at minimum: strategy freeze ID and fingerprints, governance fingerprints, verification epoch, traceability matrix hash, repository revision, working-tree state, schema/config/dependency/toolchain identity, and relevant external dependency contract identity.

The tool emits eleven fields and omits four required ones: `strategy_freeze_id`, governance fingerprint, dependency identity, and external dependency contract identity. `WORK_BASELINE_LOCK_TEMPLATE.json` lists `strategy_freeze_id` and `governance_fingerprint`, so the template and the tool disagree with each other as well as with the standard.

A lock produced by running the tool as documented is therefore not standard-conformant, and `WORK_BASELINE_LOCK_STANDARD.md` states no attempt may close without a baseline lock. Taken literally, no stage could have closed conformantly using this tool.

## Handling at this attempt

`MD-B00-A001-BL001` was generated by the tool and then augmented with the four missing fields plus code/test tree fingerprints. Tool-emitted values are preserved verbatim; the augmentation is declared inside the lock in `augmentation_note`. The lock is conformant; the tool is not.

## Required outcome

Extend the tool to emit the full minimum set natively, so the next attempt does not need manual augmentation, and reconcile `WORK_BASELINE_LOCK_TEMPLATE.json` with the standard. Until then, every attempt must repeat the augmentation, and any lock lacking the four fields should be treated as an incomplete lock rather than a valid one.
