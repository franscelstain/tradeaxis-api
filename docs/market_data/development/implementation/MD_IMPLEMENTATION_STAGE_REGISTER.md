## MD-B05-A001 — temporal identity, and three defects that only reading the contract found

`MD-B05` opened on a 78-row denominator that review replaced with 117. The prior reference set was not derived from structure: it excluded hard prohibitions — "no other classification system may be stored as `IDX-IC`", "overlapping mappings to different instruments are invalid", the whole failure-behavior list of the mapping contract — while including their siblings, and excluded two of the three contracts' acceptance criteria while marking the third required. 58 rows were promoted, 71 bound to the introducer carrying their obligation, and 20 moved to the stages that can actually execute them.

Three executable defects were found by reading the implementation against the contract, each reproduced before it was fixed.

**Board and market segment were not effective-dated.** They were single mutable columns, so recording a move meant overwriting one — rewriting every historical answer at once — and the universe query filtered on the current segment, silently removing a listing that was Regular on `T` and moved afterwards. That is the `is_active` defect in two columns the boundary does not name. `md_listing_boards` now carries the intervals; the columns stay as the cached projection the contract permits.

**The conditional `OPERATOR_ENTERED` class was unconditional at resolution.** The write path enforced the reference/operator/reason triple and the read path did not, with both columns nullable and no constraint tying them to the class — the condition checked exactly where it was already satisfied. The reproduction also surfaced a consequence nobody predicted: an ungoverned row coexisting with a governed one was counted as an overlap conflict, so the governed row resolved `UNKNOWN` too.

**A run without a config snapshot acquired with no context at all** — no knowledge cutoff, no run identity, no temporal-mapping enforcement — so provider symbols fell back to suffix rendering. The branch had outlived its cause: every run now resolves a config snapshot, so it survived only to degrade the runs that reached it.

Do-not-repeat: the relationship gate self-test removed the *last* registry row to prove completeness fails closed. That worked only while the newest edge happened to be required. This attempt registered an attempt-internal edge last, the gate correctly ignored its removal, and the self-test reported `GATE_DID_NOT_REACT` against a gate that was working. A probe whose validity depends on append order is a probe that will eventually lie in one direction or the other; it now selects an edge a record declares across a correlation boundary.

Also worth stating plainly, because the contracts insist on it: this stage establishes a survivorship-free **resolver** and an internally consistent mapping set. A survivorship-free **universe** and a complete mapping set need the external reconciliation owned by global gate 13, which `MD-B05` does not perform and does not claim.
