## E049 caller provenance and isolated execution declaration — 2026-10-23

The Project Owner's current instruction authorizes authenticated active-date writers, separately fenced append-only observers, isolated import/replay, and legitimate linked recovery. This is bounded implementation direction, not independent verification or admission. Scheduling and Locking, Run Ownership and Recovery, and Commands LOCKED remain authoritative; strategy bytes and freeze identity are unchanged.

Before production changes, the implementation contract is:

- A run model or public run ID identifies the target; it is never a credential. Fresh acquisition issues an unpredictable execution secret, persisted only as a digest. The trusted internal execution context retains the secret on its issuing database connection, outside models and exports. Loading the incumbent model or opening a competing connection cannot recover the credential. Arbitrary PHP/admin access that can directly rewrite the database is outside this application capability boundary.
- Protected writes lock the date fence, authenticate the execution credential, then validate and lock the run, in the mutation transaction. Active-run resume requires its original credential; another process refuses or follows explicit expiry/recovery. The run ID remains the ordering fence; the secret authenticates its holder.
- Import/replay require their own isolated execution capability. They may write only their own non-readable staging, lifecycle, captures and events. Publication switch, pointer, mirror, seal and recovery require publish-critical scope. AS_KNOWN retains mandatory outer rollback. Isolated execution does not acquire publication rights or authorize sealed/current mutation.
- Freshness, incident, scheduler and conflict entry boundaries explicitly acquire separate observation credentials. A role/date observation lease has its own actor, secret and monotonic token. It permits only allowlisted append-only events on explicit target history, never publication writes. The observation fence precedes target locks and spans deduplication and append; release and rollback are atomic. Historical target and acting observer are distinct identities.
- Takeover retains expiry, ambiguity, candidate-trust and prior-publication checks. Its controller must act under the acquisition lock with its own authority, never a predecessor secret. Operator apply stays BLOCKED unless linked recovery acquisition and complete target validation are implemented and proven.

Affected verification: shared writer/acquisition/event boundaries, freshness/incident/scheduler, import/replay, capture/artifact call paths, schema and focused tests. Require actor-impersonation RED/GREEN, five existing persisted controls, the eight failed regression methods, takeover/rollback and mutation restoration. Four dependency HOLDs, MD-DEP-0025, operations FAIL and inherited manual-file FAIL persist. R0004 remains incomplete. ## 2. Stage-entry normalization, and how it will be done

Every one of the 222 transitional rows was read before this declaration was written. They fall into
seven semantic classes, and the classification is recorded as an **explicit reviewed
`rule_id => decision` map with a stated basis per row** — not a keyword heuristic.

That constraint is not stylistic. `F-MD-B18-A001-001` measured what happens without it: a
`strpos()` chain over rule text put 23 of 121 predicates in a family with no keyword match at all
and let earlier branches steal predicates from later ones. `MD-B19` has 222 transitional rows and
646 reference rows, so the same shortcut here would be nine times the damage.

The classes:

| Class | Disposition | Example |
|---|---|---|
| Enumerated member of a "minimum contents / minimum artifact set / minimum evidence" list | `MANDATORY` with parent/context binding and a normalized predicate | `MD-S063-R0024` "- terminal status" |
| Question a pack must answer | `MANDATORY` with parent/context binding | `MD-S063-R0070` "1. Why was correction requested?" |
| Executable locked rule | `MANDATORY` | `MD-S070-R0018` "`eod_run_events` must be append-only" |
| Capability/citation boundary | `MANDATORY`, provable by corpus assertion | `MD-S078-R0019` "…never as evidence that operations ran correctly" |
| Cross-contract alignment pointer | `REFERENCE_ONLY` with recorded basis | `MD-S075-R0305` "- `Failure_Playbook_LOCKED.md`" |
| Purpose/scope header | `REFERENCE_ONLY` with recorded basis | `MD-S076-R0001` "Define the minimum evidence pack…" |
| Conditional obligation | `CONDITIONAL_APPLICABLE` or `CONDITIONAL_NOT_APPLICABLE`, condition named and evidenced | resolved per row |

A bullet that reads as a bare noun phrase is not thereby reference material. `- terminal status`
under "Minimum contents" is an obligation stated in list form, and
`STRATEGY_IMPLEMENTATION_TRACEABILITY_STANDARD.md` §3 requires it to carry its parent context and a
normalized predicate rather than be dropped.

The 646 `REFERENCE_ONLY` rows are examined, not accepted. This is the largest reference population
in the package and `MD-S066-R0002` survived two attempts inside one exactly like it.
